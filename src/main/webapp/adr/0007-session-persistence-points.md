# 7. Сохранение истории точек в базе данных

## Статус
Принято

## Контекст
Результаты проверки точек должны сохраняться между запросами и быть доступны всем пользователям. Требуется механизм очистки и управления историей с обеспечением персистентности данных между сессиями.

## Решение
Использовать комбинированный подход:
- База данных (JPA): Сущность `PointResult` сохраняется через `PointResultRepository`. Обеспечивает постоянное хранение
- Application-scoped Bean: `ResultsBean` хранит загруженные результаты в памяти и управляет их отображением
- Сервисный слой: `PointService` инкапсулирует бизнес-логику проверки попадания и сохранения
- Управление историей: Методы `clearResults()` и `getAllResults()` для очистки и получения всей истории

## Последствия
- Постоянство данных между сессиями и перезапусками приложения
- Масштабируемость до уровня базы данных
- Потенциальный рост таблицы при активном использовании, требующий очистки или архивации
- Application-scoped бобы могут потреблять значительную память при большом количестве результатов
- Централизованное хранение данных для всех пользователей
